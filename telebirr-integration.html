Payment Gateway Integration Guide

TeleBirr Payment Integration

A complete, verified reference for integrating TeleBirr's Fabric payment gateway into a backend + native mobile app — signing, order creation, status polling, the notify webhook, and both native SDKs. Every example uses placeholder credentials: swap in your own merchant's test keys and this works for any project.

Gateway TeleBirr Fabric API
Signature RSA-PSS (SHA256withRSAandMGF1)
Mobile Platforms Android & iOS (native SDKs)
Trust Model Webhook is a trigger, never a source of truth
01 — Overview

Project Overview

TeleBirr's Fabric integration has three moving pieces: your backend (signs and sends requests, receives the notify webhook), your mobile app (calls TeleBirr's native SDK to open the actual payment UI), and TeleBirr's gateway itself (processes the payment and unreliably calls your webhook when done).

The one rule that shapes everything Never trust a client's claim or a webhook payload that a payment succeeded. Only your backend's own signed queryOrder call to TeleBirr is a source of truth. Everything else — the mobile SDK's callback, the notify webhook — is just a trigger to go check.

How The Flow Works

flow Backend                           TeleBirr Gateway              Mobile App
 ───────                           ───────────────               ──────────
 1. POST /payment/v1/token    ───▶
    (cache the result)        ◀───  { token, effectiveTime }

 2. User taps "Pay"
    POST /payment/v1/merchant/preOrder (signed)  ───▶
                               ◀───  { prepay_id }

 3. Build receiveCode from prepay_id
    Return { receiveCode, appId, shortCode } to app  ─────────────────────▶

 4.                                                            Native SDK opens
                                                                payment UI, user
                                                                completes payment

 5. (unreliable, async)        ◀───  POST notify webhook
    Treat ONLY as a trigger —
    never trust the payload

 6. POST /payment/v1/merchant/queryOrder (signed)  ───▶
                               ◀───  { order_status: "PAY_SUCCESS" }
    THIS is what actually credits the user — not step 5.

In practice, implement both an active poll from the app (a status endpoint that internally calls queryOrder) and the notify webhook (which also just calls queryOrder). Whichever fires first wins; both paths are idempotent, so there's no double-credit risk.

Why the private key is stored with \n instead of real newlines: most .env parsers and hosting-platform env-var UIs don't handle embedded literal newlines well. Unescape it once at load time: privateKey.replace(/\\n/g, '\n').

03 — Backend Implementation

Request Signing

This is the part vendor docs get wrong most often. Verified live against TeleBirr's real gateway, and by decompiling the real SDK's bytecode:

jsconst crypto = require('crypto');
const rs = require('jsrsasign'); // npm install jsrsasign

// Fields that do NOT participate in the signature. Note biz_content itself
// is excluded, but its CHILD fields ARE flattened in and signed.
const EXCLUDE_FIELDS = [
  'sign', 'sign_type', 'header', 'refund_info',
  'openType', 'raw_request', 'biz_content', 'wallet_reference_data',
];

function signRequestObject(requestObject) {
  const fieldMap = {};
  for (const key of Object.keys(requestObject)) {
    if (EXCLUDE_FIELDS.includes(key)) continue;
    fieldMap[key] = requestObject[key];
  }
  if (requestObject.biz_content) {
    for (const key of Object.keys(requestObject.biz_content)) {
      if (EXCLUDE_FIELDS.includes(key)) continue;
      fieldMap[key] = requestObject.biz_content[key];
    }
  }
  const fields = Object.keys(fieldMap).sort(); // ASCII sort, mandatory
  const signOriginStr = fields.map((k) => `${k}=${fieldMap[k]}`).join('&');
  return signString(signOriginStr, PRIVATE_KEY_PEM);
}

function signString(text, privateKeyPem) {
  const sig = new rs.KJUR.crypto.Signature({ alg: 'SHA256withRSAandMGF1' }); // RSA-PSS, not plain RSA
  sig.init(privateKeyPem);
  sig.updateString(text);
  return rs.hextob64(sig.sign());
}

function createTimeStamp() {
  return Math.round(Date.now() / 1000) + ''; // SECONDS, not milliseconds
}

function createNonceStr() {
  // CSPRNG, not Math.random() — this becomes part of a signed request
  const chars = '0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZ';
  let str = '';
  for (const byte of crypto.randomBytes(32)) str += chars[byte % chars.length];
  return str;
}

Fabric Token & Caching

TeleBirr caps the token endpoint at 100 calls/day per Fabric App ID. Fetching a fresh token on every request will exhaust your quota within hours under real traffic.

jsconst REFRESH_MARGIN_MS = 5 * 60 * 1000;
let cached = null; // { token, expiresAt }

async function applyFabricToken() {
  if (cached && cached.expiresAt > Date.now()) {
    return { token: cached.token };
  }
  const response = await axios.post(
    `${BASE_URL}/payment/v1/token`,
    { appSecret: APP_SECRET },
    { headers: { 'Content-Type': 'application/json', 'X-APP-Key': FABRIC_APP_ID } }
  );
  const { token, effectiveTime } = response.data;
  const ttlMs = (Number(effectiveTime) || 7200) * 1000;
  cached = { token, expiresAt: Date.now() + Math.max(ttlMs - REFRESH_MARGIN_MS, 0) };
  return { token };
}

Create Order (preOrder)

jsasync function createOrder({ title, amount, merchOrderId, notifyUrl }) {
  const { token } = await applyFabricToken();

  const req = {
    timestamp: createTimeStamp(),
    nonce_str: createNonceStr(),
    method: 'payment.preorder',
    version: '1.0',
  };
  req.biz_content = {
    notify_url: notifyUrl,
    appid: MERCHANT_APP_ID,
    merch_code: MERCHANT_CODE,
    merch_order_id: merchOrderId,
    trade_type: 'Cross-App', // standalone native app; not the vendor doc's "InApp" example
    title,                   // see Pitfalls — forbidden characters will 400 this
    total_amount: String(amount),
    trans_currency: 'ETB',
    timeout_express: '120m',
    business_type: 'BuyGoods',
  };
  req.sign = signRequestObject(req);
  req.sign_type = 'SHA256WithRSA';

  const response = await axios.post(
    `${BASE_URL}/payment/v1/merchant/preOrder`,
    req,
    { headers: { 'Content-Type': 'application/json', 'X-APP-Key': FABRIC_APP_ID, Authorization: token } }
  );

  if (response.data.result !== 'SUCCESS') {
    throw new Error(response.data.msg || 'TeleBirr pre-order failed');
  }
  return response.data.biz_content.prepay_id;
}

Query Order Status — Your Actual Source of Truth

jsasync function queryOrder(merchOrderId) {
  const { token } = await applyFabricToken();
  const req = {
    timestamp: createTimeStamp(),
    nonce_str: createNonceStr(),
    method: 'payment.queryorder', // confirmed live: must be lowercase exactly like this
    version: '1.0',
  };
  req.biz_content = { appid: MERCHANT_APP_ID, merch_code: MERCHANT_CODE, merch_order_id: merchOrderId };
  req.sign = signRequestObject(req);
  req.sign_type = 'SHA256WithRSA';

  const response = await axios.post(
    `${BASE_URL}/payment/v1/merchant/queryOrder`,
    req,
    { headers: { 'Content-Type': 'application/json', 'X-APP-Key': FABRIC_APP_ID, Authorization: token } }
  );
  return response.data; // check .biz_content.order_status: "PAY_SUCCESS" | "PAY_FAILED" | "WAIT_PAY"
}

Notify Webhook — The Critical Security Boundary

This endpoint is unauthenticated and internet-facing by necessity. Anyone can POST here with any merch_order_id claiming success. Never credit a balance based on what the request body claims.

jsrouter.post('/telebirr/notify', async (req, res) => {
  const { merch_order_id: merchOrderId } = req.body || {};
  res.status(200).json({ received: true }); // ack immediately, per TeleBirr's spec
  if (!merchOrderId) return;

  try {
    const result = await queryOrder(merchOrderId); // independently re-verify — never trust req.body
    const status = result?.biz_content?.order_status;
    if (status === 'PAY_SUCCESS') {
      await settleOrder(merchOrderId, 'success', result.biz_content.payment_order_id, result.biz_content.trans_id);
    } else if (status === 'PAY_FAILED') {
      await settleOrder(merchOrderId, 'failed', result.biz_content.payment_order_id, result.biz_content.trans_id);
    }
  } catch (err) {
    console.warn(`notify-triggered queryOrder failed for ${merchOrderId}:`, err.message);
  }
});

// Idempotent — only updates a row still 'pending', so a race between the
// webhook and an active poll (or a retried webhook delivery) can never
// double-credit the same order.
async function settleOrder(merchOrderId, status, paymentOrderId, transId) {
  const updated = await db.markStatus(merchOrderId, status, paymentOrderId, transId); // WHERE status = 'pending'
  if (!updated) return; // already settled by a concurrent caller
  if (status === 'success') await db.creditBalance(updated.user_id, updated.amount);
}
04 — Mobile Integration

Building receiveCode

Both the Android and iOS native SDKs need this string, built server-side after preOrder returns:

formatTELEBIRR$BUYGOODS$<merchantCode>$<amount, 2 decimals>$<prepay_id>$<yyyyMMddHHmmss, UTC>

Example: TELEBIRR$BUYGOODS$554722$50.00$010e7c6b042ef6e856851c12c6ed1a6cdfe0901$20260925104043

jsfunction buildReceiveCode({ amount, prepayId }) {
  const d = new Date();
  const pad = (n) => String(n).padStart(2, '0');
  const time = `${d.getUTCFullYear()}${pad(d.getUTCMonth() + 1)}${pad(d.getUTCDate())}${pad(d.getUTCHours())}${pad(d.getUTCMinutes())}${pad(d.getUTCSeconds())}`;
  return `TELEBIRR$BUYGOODS$${MERCHANT_CODE}$${Number(amount).toFixed(2)}$${prepayId}$${time}`;
}
Do not trust the vendor doc here It shows BUYGOOD (no S) with %{time} as the separator before the timestamp. Verified by decompiling the real TeleBirr customer app's bytecode: it's BUYGOODS (plural), $-delimited throughout, no exceptions. The vendor doc's own worked example even uses BUYGOODS right below its wrong format line — it's an internally inconsistent document, not just stale.

Android Native SDK

TeleBirr distributes EthiopiaPaySdkModule-*.aar — Android only, local-dependency mode (no Maven/CocoaPods equivalent).

kotlinimport com.huawei.ethiopia.pay.sdk.api.core.data.PayInfo
import com.huawei.ethiopia.pay.sdk.api.core.listener.PayCallback
import com.huawei.ethiopia.pay.sdk.api.core.utils.PaymentManager
import androidx.fragment.app.FragmentActivity // NOT a plain Activity — see Pitfalls

fun startPay(activity: FragmentActivity, appId: String, shortCode: String, receiveCode: String) {
  val payInfo = PayInfo.Builder()
    .setAppId(appId)
    .setShortCode(shortCode)
    .setReceiveCode(receiveCode)
    .build()

  PaymentManager.getInstance().setPayCallback(object : PayCallback {
    override fun onPayCallback(code: Int, msg: String) {
      // code 0 = success. -1 unknown, -2 param error, -3 cancelled,
      // -10 not installed, -11 unsupported version.
    }
  })
  PaymentManager.getInstance().pay(activity, payInfo)
}

Gradle setup — the AAR needs flatDir resolution, not files() (see Pitfalls):

groovy// repositories block, visible to whichever project resolves the final app

}
dependencies {

}

05 — Reference

Security Checklist

  • 1Notify webhook never credits a balance directly from the request body — always re-verify via queryOrder.
  • 2nonce_str and merchant order IDs use a CSPRNG (crypto.randomBytes), never Math.random().
  • 3Fabric token is cached in-memory, not fetched per-request (100 calls/day limit).
  • 4Rate limiting on order-creation endpoints — not status-polling, which is called far more often per legitimate payment.
  • 5Settlement is idempotent (UPDATE ... WHERE status = 'pending') so a webhook race or retry can't double-credit.
  • 6Private key and app secret are never logged or committed to git.
  • 7Production and sandbox credentials are never mixed in the same deploy.

Hard-Won Pitfalls

These cost real debugging time — save yourself the trouble.

1. title field rejects special characters

TeleBirr's own pattern is [^~`!#$%^*()\-+=|/<>?;:"\[\]{}\\&]* — notably hyphens are forbidden. "Wallet Top-Up" gets rejected with a cryptic biz_content.title type mismatch error. Use "Wallet Topup" instead.

2. Sandbox host has an unverifiable TLS certificate

developerportal.ethiotelebirr.et fails with unable to verify the first certificate on a normal HTTP client. Relax rejectUnauthorized only for that specific host — never globally, or you silently weaken your production client too.

3. Android's PaymentManager.pay() requires FragmentActivity, not Activity

Verified by decompiling the AAR's actual classes.jar with javap — the vendor doc's Java snippet doesn't make this clear. A plain Activity reference causes a Kotlin compile error, not a runtime one.

4. Local .aar dependencies need flatDir + name/ext notation

Plain implementation files('libs/x.aar') does not reliably resolve a local AAR's classes onto the Kotlin compile classpath. And flatDir-resolved dependencies carry no transitive metadata — if the AAR itself depends on something (like androidx.fragment), declare that dependency explicitly yourself.

5. CNG-managed mobile projects (Expo) need a config plugin, not a hand-edit

If your native android//ios/ folders are gitignored and regenerated fresh by every cloud build, any native build-file edit must go through a config plugin — a direct hand-edit silently never reaches your build server.

6. receiveCode's separator is $, not %, and it's BUYGOODS not BUYGOOD

See the receiveCode section above — this is the single most common copy-paste error from the vendor documentation.

7. iOS does have an SDK

Don't assume WebView-only integration without actually checking — TeleBirr just documents iOS far less than Android.

Testing: Sandbox vs Production

SandboxProduction
Real money moves?NoYes
TLS cert trusted by default?NoYes
Separate credentials?Yes, own merchant accountYes, own merchant account
Diagnosing a sandbox outage If your sandbox account ever returns errorCode 49401024991 ("southbound business service unavailable"), that's TeleBirr's own sandbox infrastructure being down — not your integration. Confirm with a plain connectivity check (nc -zv <ip> 38443) before assuming a code bug.

Before going live: confirm with TeleBirr which IP(s) and port need whitelisting for your production server (both for outbound calls to their gateway and for them to reach your notify URL), and confirm your notify_url is a real, publicly reachable HTTPS URL — TeleBirr's own spec requires it.
